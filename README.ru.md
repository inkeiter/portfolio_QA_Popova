# 🧪 QA Engineer Portfolio | Функциональное, API-тестирование и автоматизация

> 🇬🇧 English version: [README.md](README.md)

Привет! Я начинающий QA-инженер с 6 месяцами коммерческого опыта тестирования веб-сервисов. В этом репозитории собраны мои практические работы по тест-дизайну, API-тестированию и автоматизации UI и API, в том числе с использованием AI-инструментов.

## 🛠 Навыки

**Тестирование:** функциональное, регрессионное и приёмочное; техники тест-дизайна (эквивалентные классы, граничные значения)  
**API и инструменты:** Postman, Swagger, DevTools, Jira  
**Автоматизация:** Java (Selenide, RestAssured, JUnit 5), Python (Playwright, pytest)  
**CI и контроль версий:** Git, GitHub, GitHub Actions, AppVeyor  
**Данные:** SQL (PostgreSQL), простые запросы для проверки корректности данных  
**AI-инструменты:** ChatGPT и Claude для написания SQL-запросов и генерации простых автотестов; сгенерированный код я проверяю и запускаю сама

## 📂 Проекты

**1. E2E-тесты (UI + API) для банковского приложения**
*   **Стек:** Java 11, Selenide, RestAssured, JUnit 5, JavaFaker, Gradle, CI (AppVeyor)
*   **Описание:** Автоматизированные тесты пользовательского интерфейса (UI) и API тестового банковского приложения.
*   **Ключевые особенности:**
    *   Паттерн Page Object
    *   UI-тесты: авторизация, заполнение форм, проверка навигации и элементов
    *   API-тесты: запросы к эндпоинтам, проверка ответов и структуры JSON
    *   Валидные случайные данные для форм через JavaFaker (без захардкоженных значений)
    *   Непрерывная интеграция в AppVeyor: при каждом пуше запускается сервер приложения и тесты в headless-режиме
*   🔗 [Код на GitHub](https://github.com/inkeiter/e2e-testing-java-selenide)

**2. QA-документация**
*   **Стек:** Jira (формат баг-репортов), Markdown, терминология ISTQB
*   **Описание:** Артефакты ручного тестирования, показывающие анализ требований, тест-дизайн и понятное оформление документации.
*   **Ключевые особенности:**
    *   Структурированные тест-кейсы с шагами, тестовыми данными и ожидаемыми результатами
    *   Чек-листы для функционального тестирования веб-форм (позитивные и негативные сценарии)
    *   Примеры баг-репортов в формате Jira с severity, priority и шагами воспроизведения
*   🔗 [Документация на GitHub](https://github.com/inkeiter/qa-documentation)

**3. AI-assisted E2E-тестирование (Playwright + Python)**
*   **Стек:** Python, Playwright, pytest, GitHub Actions, AI-ассистент (Claude)
*   **Описание:** Учебный проект о том, как генеративный AI может ускорять автоматизацию тестирования, с проверкой каждого результата человеком.
*   **Ключевые особенности:**
    *   Два E2E-теста для учебного сайта Sauce Demo: успешный вход и негативный сценарий с неверным паролем
    *   Устойчивые локаторы и автоматические ожидания Playwright, без `sleep`
    *   CI в GitHub Actions
    *   Написание промтов, запуск сгенерированного кода и отладка ошибок как в ответе AI, так и в самом тесте
    *   Изучение Playwright с нуля с помощью AI-инструментов
*   🔗 [Код на GitHub](https://github.com/inkeiter/saucedemo-ai-e2e)
